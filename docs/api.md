# API reference

Base URL when running locally: `http://localhost:8000`. Interactive documentation, generated by FastAPI from the
code, is at <http://localhost:8000/docs> (Swagger UI) and <http://localhost:8000/redoc>; the machine-readable
schema is at `/openapi.json`. This page is a summary of the conventions and of every endpoint.

## Conventions

* JSON in, JSON out. Every endpoint except the two `GET`s below is a `POST` with a JSON body.
* **Limits.** Text: at most 10,000 characters. Keys of the Caesar and affine ciphers: integers with absolute value
  at most 9007199254740991 (2⁵³ − 1). Vigenère keyword: 1 to 64 letters. Request body: at most 256 KiB. These are
  API limits, not mathematical ones.
* **Letters.** Only the 52 ASCII letters are processed; case is preserved by the ciphers and ignored by the
  analysis. Everything else (spaces, digits, punctuation, non-ASCII characters) is copied by the ciphers and
  ignored by the analysis.
* **Errors** always have the same body, with at most 20 entries, as plain ASCII, and without echoing the input:

  ```json
  {"detail": [{"loc": ["body", "key"], "msg": "…", "type": "invalid_key"}]}
  ```

| Status | Meaning | Common `type` values |
| --- | --- | --- |
| 413 | body larger than 256 KiB | `payload_too_large` |
| 422 | malformed request, or a mathematically invalid or unusable input | validation types, `invalid_key`, `no_letters`, `insufficient_text`, `invalid_key_length` |
| 404 / 405 | unknown route / wrong method | `not_found`, `method_not_allowed` |
| 500 | unexpected failure; generic body, details only in the server log | `internal_error` |

## Service

| Method and path | Reply |
| --- | --- |
| `GET /` | service banner (name, description, version, links) |
| `GET /api/v1/health` | `{status, service, version, message, timestamp}` |
| `GET /api/v1/modules` | the registered backend modules (`algebra`, `analysis`) and their status |

## Ciphers: `/api/v1/algebra`

All four Caesar and affine endpoints and both Vigenère endpoints return the input, the output and the key as
used. Mathematics: [Caesar and affine](mathematics/caesar-and-affine.md), [Vigenère](mathematics/vigenere.md).

| Endpoint | Body | Notes |
| --- | --- | --- |
| `POST /algebra/caesar/encrypt`, `/decrypt` | `{"text", "key"}` | `key` any integer within ±(2⁵³ − 1); reply has `effective_key` = `key mod 26` |
| `POST /algebra/affine/encrypt`, `/decrypt` | `{"text", "a", "b"}` | `gcd(a, 26)` must be 1, otherwise 422 `invalid_key` (location `["body", "a"]`); reply has `effective_a`, `effective_b`, `a_inverse` |
| `POST /algebra/vigenere/encrypt`, `/decrypt` | `{"text", "key"}` | `key` a keyword of 1 to 64 ASCII letters, otherwise 422 `invalid_key`; reply has `key_shifts` and `key_length` |

Example:

```text
POST /api/v1/algebra/vigenere/encrypt   {"text": "Attack at Dawn!", "key": "Lemon"}
→ {"cipher": "vigenere", "operation": "encrypt", "input": "Attack at Dawn!", "output": "Lxfopv ef Rnhr!",
   "key": "Lemon", "key_shifts": [11, 4, 12, 14, 13], "key_length": 5}
```

## Analysis: `/api/v1/analysis`

Mathematics: [Frequency analysis](mathematics/frequency-analysis.md),
[Polyalphabetic analysis](mathematics/polyalphabetic-analysis.md). Every ranking is a statistical estimate and
carries a `reliability` of `very_low`, `low` or `adequate`.

| Endpoint | Body | Reply |
| --- | --- | --- |
| `POST /analysis/frequency` | `{"text"}` | per-letter counts, shares, English comparison, ranks, χ² and the index of coincidence (`null` below two letters), character breakdown. A text without letters is valid (all zeros). |
| `POST /analysis/caesar/crack` | `{"text"}` | all 26 keys ranked by χ², with decrypted text. No letters → 422 `no_letters`. |
| `POST /analysis/affine/search` | `{"text", "plaintext_limit"?}` | all 312 valid keys ranked by χ²; decrypted text for the best `plaintext_limit` (0 to 312, default 20). No letters → 422 `no_letters`. |
| `POST /analysis/vigenere/lengths` | `{"text"}` | index of coincidence with reading and Friedman estimate; Kasiski repeats and key-length votes; key lengths 1 to 20 ranked by mean column IC; suggested length (or `null`). Fewer than two letters → 422 `insufficient_text`. |
| `POST /analysis/vigenere/candidates` | `{"text", "key_length"}` | for a key length from 1 to 40: per-column key letter with alternatives; up to 10 ranked candidate keys with decrypted text. `key_length` larger than the number of letters → 422 `invalid_key_length`. |

## Versioning

The API is versioned in the path (`/api/v1`). The backend and frontend report the same application version
(`1.0.0`), shown in `GET /api/v1/health` and in Settings.
